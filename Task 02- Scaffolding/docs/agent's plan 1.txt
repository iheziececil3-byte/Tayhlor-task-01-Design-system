### 1. Structured Summary of Understanding

#### 1.1 Product Understanding
- **What Tayhlor is**: A single-tenant web application dedicated to one bespoke tailoring business: **D Williams Fashion Hub** (PRD Section 1, 4.2). It centralizes customer profiles, precise body measurements, bespoke clothing orders, two-stage deposit/balance payments, and order progress tracking.
- **The Problem It Addresses**: Replaces chaotic manual processes—lost physical measurement notes, undocumented verbal agreements, unverified bank payments, and repetitive manual customer status inquiries ("is my garment ready?")—with an accountable, single-source-of-truth digital workflow.
- **Intended Users**:
  1. **Customer**: Adults (ages 18–75) in Nigeria and the diaspora, accessing the platform primarily on smartphones over mobile cellular connections. Customers register, verify email, maintain custom measurement records, submit orders, pay a 70% deposit upon tailor acceptance, pay the 30% balance upon collection for fitting, track live status, request personal data export/deletion, and ask business questions via an AI FAQ assistant grounded exclusively in tailor-approved documents.
  2. **Tailor (Admin)**: The artisan and shop owner (who is also the developer). The tailor manages the incoming order queue, reviews measurement snapshots, sets exact quoted prices (in NGN kobo) and proposed completion dates, updates order statuses (`IN_PROGRESS`, `READY_FOR_COLLECTION`, `COMPLETED`), logs fitting outcomes (`SATISFACTORY` or `ALTERATIONS_REQUIRED`), records customer contact edits, manages approved FAQ documents, monitors Paystack payments, and logs manual refunds.

#### 1.2 Technical Direction
- **Framework**: Next.js with App Router, TypeScript, and React (Locked per PRD 8.1).
- **ORM & Database**: Prisma ORM with PostgreSQL and `pgvector` hosted through Vercel Marketplace. Pooled connection for runtime queries; direct connection for Prisma CLI/migrations (PRD 8.2). All data models enforce the mandatory `recordEnvironment` safeguard to isolate test activity from genuine customer data.
- **Styling Architecture**: Tailwind CSS mapped directly to Tayhlor's Tier 2 semantic CSS design tokens.
- **Typography Integration**: `next/font/google` loading Google Fonts `Lora` (Editorial Serif for Display/Headlines) and `Manrope` (Modern Sans for UI Title/Body/Label) with zero layout shift and local pre-loading.
- **Payments**: Paystack in test mode (NGN stored as integer kobo). 70% deposit and 30% balance calculated server-side. Verification via server-side API and HMAC SHA-512 webhooks (browser redirects never confirm payment). Flutterwave deferred.
- **Communications**: Resend API for transactional notifications (active only with verified domain).
- **Authentication**: Auth.js (NextAuth v5) supporting credentials (Argon2id password hashing) and Google sign-in.
- **AI FAQ Grounding**: Google Gemini API for embeddings and generation; cosine similarity retrieval against approved `FAQChunk` records. Strict fallback decline text when unverified.
- **Tooling Environment**: Node.js `v24.19.0`, npm `11.17.0` (using `npm.cmd` on Windows due to PowerShell execution policy).

The project foundation will be established in the workspace root with standard Next.js App Router conventions:
